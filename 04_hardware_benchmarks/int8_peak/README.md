# C500 INT8 MMA 吞吐测试

## 当前进度

2026-10-21：已实现设备查询、配置检查、输入准备、INT8 MMA kernel、
1/2/4/8/16 累加器分派、完整输出校验、Event 计时、结果打印与单配置 main 入口。
支持单配置运行和 block 数、线程数、累加器数的固定范围扫描。
扫描按平均耗时计算的 TOPS 排名；最高值只代表本次测试范围和当前实例环境。
新增扩大扫描与长批次验证入口，用于完整 C500 的复核；原扫描入口和历史报告保留。

## 测试目标

测量当前实例通过 INT8 矩阵乘加指令能够达到的计算吞吐，单位 TOPS。
这是当前环境与测试配置下的实测值，不直接等同于芯片官方理论峰值。
本目录聚焦 INT8 MMA，不调用 mcBLAS 或其他 GEMM 库来代替指令测试。

计划让数据主要驻留寄存器，减少显存访问的干扰，观察矩阵计算管线的吞吐。
测试结果不是完整 GEMM 或 fused MoE 的端到端性能。

## 构建与运行

在 C500 上进入本目录：

```bash
cd /root/MOE/C500_int8_02All/04_hardware_benchmarks/int8_peak
bash build.sh
```

构建成功后运行默认的正确性演示配置（1 block、64 线程、1 累加器、4096 次循环）：

```bash
./build/int8_mma_peak
```

也可以指定一个配置，四个参数依次为 block 数、每 block 线程数、独立累加器数、循环次数：

```bash
./build/int8_mma_peak 1 64 4 4096
./build/int8_mma_peak --help
```

累加器数量支持 `1、2、4、8、16`，循环次数为 `1..8191`。
线程数必须是 64 的正整数倍，并满足设备和所选 kernel 的线程上限；
当前 SDK 下五种 kernel 的线程上限实测均为 512。
参数错误或正确性失败均返回非零退出码。
输出包含配置、单次 kernel 的 OPS、三次耗时及对应 TOPS、平均耗时、
按平均耗时计算的主 TOPS 和正确性状态。校验失败时不输出有效 TOPS。
计时覆盖完整 kernel，包括热循环前的加载及循环后的结果写出，不做空 kernel 扣时。
默认小配置只用于跑通执行流程；单配置结果不作为峰值吞吐结论。

脚本自动定位自身目录、创建 build 目录、设置动态库路径并写入 rpath。
默认 SDK 为 /opt/maca，可通过 MACA_PATH 指定其他安装位置。
编译参数为 `-O3 -std=c++17 -x maca -offload-arch=xcore1000`，目标为 C500。
构建脚本只负责编译，不自动执行 benchmark；构建脚本不接收命令行参数。

## 扫描与选择最佳配置

```bash
./build/int8_mma_peak --scan
# 可指定统一循环次数与新的 CSV 路径；日志与 CSV 分开保留。
./build/int8_mma_peak --scan 4096 reports/int8_scan_example.csv \
    > reports/int8_scan_example.log 2>&1
```

默认扫描范围：

| 配置项 | 候选值 |
| --- | --- |
| block 数 | 1、8、16、32、64、104、208、416、832 |
| 每 block 线程数 | 64、128、256、512 |
| 每 wave 独立累加器数量 | 1、2、4、8、16 |
| 循环次数 | 所有配置统一为 4096 |

共 180 个候选配置。先查询各模板的资源限制，不支持的线程数会跳过并记录数量。
block 数是绝对启动数；104 只是候选值，不用于推定实例独享 104 个 AP。
固定种子 `20261021` 打散配置执行顺序，CSV 的 order 列保留本次实际顺序。
每个配置独立准备输入，预热 1 次、测量 3 次、检查所有 wave/累加器输出。
正确性失败立即停止并保留已有 CSV，不输出扫描最佳结论。

CSV 保存配置、wave 数、OPS、三次原始耗时和 TOPS、平均耗时、
按平均耗时计算的 TOPS、样本极差/中位数、正确性以及模板的寄存器/本地/共享内存信息。
这里的波动指标来自同一配置的三次样本，尚未做多轮完整扫描。
排名指标为 `total_ops / (mean_ms * 1e9)`，不是最快的单次样本或三次 TOPS 的平均。
终端输出前 5 名及第 1 名的完整数据；只在实际通过检查的配置之间选择最佳值。

默认 CSV 名为 `reports/int8_scan_<epoch_ms>.csv`。指定的 CSV 已存在时拒绝覆盖，
父目录须事先存在。扫描程序不自动判断其他作业是否静默；正式计时前应使用共享锁，
取得静默确认，并另存环境、源码哈希和编译信息。未取得确认的扫描须标为探索性结果。

## 扩大范围与长批次验证

```bash
# 原有 180 个配置，加上 blocks=1664、3328、6656，共 240 个配置。
./build/int8_mma_peak --scan-wide 4096 reports/new_wide.csv

# blocks、线程/block、累加器/wave、循环次数、样本数、每样本 kernel 数、CSV 路径。
./build/int8_mma_peak --sustain 6656 512 8 4096 10 4 reports/new_sustained.csv
```

长批次入口先做数值预检，再连续预热至少 2 秒。每个正式样本把指定数量的相同 kernel
放入同一对 Event 之间，同时用 CPU `steady_clock` 记录提交到等待结束的墙钟时间。
两种计时均排除分配、输入拷贝、输出初始化、回读、数值校验和打印。
Event 包含整个 kernel 批次及其中的设备端间隙；墙钟还包含 Event/kernel 提交和等待的开销。
不能将这个墙钟结果称为包含数据准备的端到端 MoE 吞吐。

```text
每批次 OPS = 单个 kernel 的 OPS × kernels_per_sample
批次 TOPS = 每批次 OPS / (对应批次耗时 ms × 1e9)
```

每次 kernel 都从零初始化寄存器累加器，因此 batch 不会增加单个 INT32 输出的累加次数。
每个样本结束后校验最后一个 kernel 的所有 wave/累加器输出；batch 内各次 kernel
覆盖同一输出缓冲区，不逐个保留中间输出。计时前也单独检查一次 kernel 的数值结果。
CSV 逐样本保留 Event 和墙钟耗时、两种 TOPS、精确 OPS 和正确性状态。
样本数允许 `1..1000`，batch 允许 `1..10000`；每个 CSV 路径须为尚不存在的文件。

完整设备的复核采用独立多轮运行，改变候选配置的轮内顺序，保留每轮全部样本。
主要吞吐仍按所有同配置样本的平均耗时计算。另记录三轮均值的范围和温度、时钟、
功耗、限频原因；不把单次最大 TOPS 当成稳定峰值。

## 约定的计时方法

- 先执行 1 次预热并等待完成，预热不计入统计。
- 正式测量 3 次，每次用同一条流中的 mcEvent 开始与结束事件包围待测 kernel。
- 先提交结束事件，再检查启动错误；等待结束事件后读取本次耗时。
- 保留三次原始耗时 t1、t2、t3，报告算术平均耗时：
  `mean_ms = (t1 + t2 + t3) / 3`。
- 显存分配、输入准备、数据拷贝、CPU 校验与打印放在计时区间外。
- kernel 内需要足够计算量，减小事件与提交间隙对短任务的影响；与 profiler 采样结果分开记录。

主吞吐指标按平均耗时计算，不是先计算三个 TOPS 再取平均：

```text
TOPS = 本次 kernel 的总运算次数 / (mean_ms × 10^9)
```

## 运算量计算规则

INT8 输入、INT32 累加；采用 C500 的 `__builtin_mxc_mma_16x16x16i8`。
对于完整的 16×16×16 MMA，一条 wave 协作指令包含：

```text
16 × 16 × 16 = 4096 次乘加
4096 × 2     = 8192 OPS
```

一次乘法和一次加法各计 1 OPS，8192 已包含这个 ×2。
一条 wave 协作 MMA 按一次计算，不把它再次乘以 wave 内的线程数。
总运算量按实际执行的指令类型、wave 数、循环次数及每轮的 MMA 次数计算，并与生成代码核对。

```text
单次 kernel 总 OPS = blocks × (threads_per_block / 64) × accumulators × iterations × 8192
```

不包含预热，也不乘三次测量次数。每次测量执行相同工作量。

8192 OPS/指令不代表 8192 MAC/AP/cycle。
不预设每 AP 每周期的指令吞吐，也不使用尚未验证的假设作为测试结果。

## 后续实现与验证要求

1. 构造不会造成 INT32 累加溢出的输入，检查结果正确。
2. 将累加结果写出并校验，确认编译器没有删除待测计算。
3. 使用足够的并行任务和适当数量的独立累加链，区分吞吐不足与依赖延迟。
4. 核对编译器输出中的 INT8 MMA 指令及其数量，再核算总运算量。
5. 记录当前实例实际达到的吞吐；只在测试过的配置范围内讨论最高值。

报告计划包含源码版本/哈希、编译参数、启动配置、循环次数、
三次原始耗时、平均耗时、总 OPS、TOPS、正确性检查和设备环境。

设备记录需区分运行时上报属性、DPM 频率档位、运行时频率以及 sGPU 配额。
