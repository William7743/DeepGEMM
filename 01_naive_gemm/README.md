# 朴素 INT8 GEMM：加入 scale

本课只完成单个矩阵乘法的编译、执行与正确性检查：

```text
A: INT8  [M, K]
B: INT8  [K, N]
A_scale: FP32 [M]  每行一个系数
B_scale: FP32 [N]  每列一个系数
C: FP32 [M, N]
sum = sum(A[row,p] * B[p,col]), p = 0..K-1，INT32 累加
C[row,col] = float(sum) * A_scale[row] * B_scale[col]
```

三个矩阵均按行存储。一个 GPU 线程计算一个 C 元素；每个 block 有 16×16 个线程。grid 的 x 方向覆盖输出列，y 方向覆盖输出行。边界判断允许 M、N 不整除 16。

这是普通的 B[K,N] 布局；后续适配 DeepGEMM 的 NT 接口时，再引入权重 B[N,K] 的存储布局。本课还没有专家分组、量化过程、共享内存分块或 MMA 优化。输入本来就是 INT8，因此也不测量浮点模型的量化误差。

本步约定对称量化、零点为 0：浮点值近似为 `INT8值 × scale`。A 的 scale 沿 K 不变，B 的 scale 也沿 K 不变，因此两个 scale 可以提到求和之外，在写回时相乘。本例手动提供不同的 scale：A 每行依次为 0.1、0.2…0.7，循环；B 每列依次为 0.2、0.4…1.0，循环。尚未实现从浮点输入计算 scale 或量化。

核心变化只有：

```cpp
c[row * n + col] = static_cast<float>(sum) * a_scale[row] * b_scale[col];
```

累加仍是 INT32，输出缓冲区变成 `float`，并为两个 scale 数组增加 GPU 分配、拷贝与释放。例如默认用例的首元素，整数点积为 48，写回值约为 `48 × 0.1 × 0.2 = 0.96`。

## 编译与执行

在 C500 服务器运行：

```bash
cd /root/MOE/C500_int8_02All/01_naive_gemm
bash build.sh
export LD_LIBRARY_PATH=/opt/maca/lib:/opt/mxdriver/lib:${LD_LIBRARY_PATH:-}

./naive_gemm.out              # M=3, N=4, K=5，打印输出矩阵
./naive_gemm.out 17 19 23     # 检查不整除 block 大小的边界
./naive_gemm.out 64 96 128    # 覆盖多个完整 block
```

参数顺序为 `M N K`，为控制本课规模，每个维度限制在 1～1024。测试输入确定性生成，范围为 -8～8，包含正数、负数和零。最大累加绝对值不超过 65536，INT32 不会溢出。

程序使用 CPU INT64 点积、FP64 缩放计算参考值，逐元素检查全部 GPU 输出。FP32 乘法可能有舍入误差，不再要求误差必须为零；采用 `abs(gpu-reference) <= 1e-6 + 1e-5*abs(reference)`。成功应显示 `mismatches=0` 和 `PASS`。相对误差只统计 `abs(reference)>1e-6` 的元素。这一步不做性能评测。

## 建议阅读顺序

1. `naive_int8_gemm`：线程的 row/col 怎么算，为什么需要边界判断。
2. `main` 第 1～2 步：CPU 数据、GPU 内存分配、输入拷贝。
3. 第 3～4 步：grid/block、kernel 启动、同步和结果拷回。
4. 第 5 步与 `reference_gemm`：如何知道结果正确。

重点先解释三个下标：`a[row*k+p]`、`b[p*n+col]`、`c[row*n+col]`。编译和运行成功后，先弄懂这一步，再增加后续功能。
