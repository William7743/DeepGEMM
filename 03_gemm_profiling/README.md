# C500 矩阵乘性能分析练习

## 第一课：朴素 INT8 矩阵乘

本课只实现正确计算与可复现构建。尚未加入性能计时或 profiler 采样，因此没有性能基线，也不对瓶颈下结论。

### 输入和输出

`A[M,K] × B[K,N] = C[M,N]`。三者均为连续行主序，A/B 为 INT8，累加与 C 为 INT32。
B 实际存成 K 行、N 列，与之前 grouped GEMM 中按 N×K 存储的权重约定不同。
输入直接生成确定性的 [-128,127] 整数，不包含浮点量化或 scale。

- M：A/C 的行数。
- N：B/C 的列数。
- K：点积长度。
- 教学入口范围：1≤M,N≤4096，1≤K≤32768；这是本练习的限制，并非 C500 的硬件限制。
- K 上限保证全范围 INT8 点积不会溢出 INT32：32768×16384=536870912。
- 每次完整 CPU 校验的工作量随 M×N×K 增长，初学先用小矩阵。

### 构建和运行

在 C500 上执行：

```bash
cd /root/MOE/C500_int8_02All/03_gemm_profiling
bash build.sh
./build/gemm
./build/gemm 3 5 7
./build/gemm 17 19 33
./build/gemm 64 96 128
```

可执行文件在已忽略的 `build/` 中；脚本设置运行库搜索路径并写入 rpath。
无参数时 M=N=K=64；指定尺寸时顺序为 M N K。

程序打印设备、尺寸、全量校验元素数、不一致个数、最大绝对误差。
成功条件为 `mismatches: 0`、`max_abs_error: 0` 和 `PASS`，退出码为 0。

### 按这个顺序读源码

1. `naive_int8_gemm`：线程如何找到 C 中的一个元素。
2. 点积循环：A 的一行与 B 的一列逐项相乘并累加。
3. `main` 中的 host 数据生成、显存申请与拷贝。
4. `grid/block`、核函数启动、错误检查与同步。
5. INT64 CPU 参考：检查每个输出，整数结果要求完全一致。

关键索引：

```cpp
a[row * K + p] // 第 row 行、第 p 列
b[p * N + col] // 第 p 行、第 col 列
c[row * N + col]
```

`block(16,16)` 是 256 个线程，每个线程只算一个 C 元素。
这个版本没有共享内存 tile；线程块形状不代表使用了硬件矩阵指令。
grid 向上取整，`row >= M || col >= N` 的线程直接返回，不访问越界地址。
C 只分配 M×N 个元素，不要求把矩阵补成 16 的整数倍。

核函数提交后，`mcGetLastError` 检查启动错误，
`mcDeviceSynchronize` 等待执行并检查错误，再拷回输出。显式同步是本课的校验流程，不是性能计时。

### 本课验收

2026-10-20 已在 C500（MACA 3.7.1.5、25% 算力 / 16 GB sGPU）编译并运行：

- 8 组 GPU 全量校验通过：默认 64×64×64、1×1×1、3×5×7、16×16×16、17×19×33、64×96×128、17×257×259、1×2×32768；顺序均为 M×N×K。
- 5 组非法参数检查通过：零尺寸、参数数量不对、非数字、K 超上限、M 超上限。
- 正常 case 的每个输出均与 CPU INT64 参考完全相同，最大绝对误差为 0。

原始输出、退出码、源码 SHA256 和设备信息保存在 [正确性记录](reports/naive_correctness_2026-10-20.json)。
本课只记录正确性和环境，不记录耗时；后续先定义计时口径、验证工具采样，再依据数据选择优化。

后续仍在同一个 `gemm.cpp` 中逐步修改，用 Git 历史查看变化。
